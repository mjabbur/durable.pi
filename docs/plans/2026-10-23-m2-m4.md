# Plano M2 → M4

Escrito em 2026-10-23, sobre `main` em `f50da1b`. Meta: fechar a paridade
funcional do CLI (M2) e o resto da paridade do Pi (M4), sem abrir mão das
invariantes duráveis. M3 (servidor/web) fica entre os dois e não é detalhado
aqui além das dependências.

## Critério de pronto (vale para todo PR)

1. Spec em `specs/<slug>/spec.md` antes do código.
2. Teste de contrato gerado pelo muse; fallback manual declarado na spec quando
   o gerador não compilar (TUI/CLI) — nada de editar `test/spec/` à mão.
3. Gates: `npm run typecheck && npm run lint && npm test`.
4. Auditoria do Sol no diff, com cada achado verificado e corrigido/declarado.
5. PR squash com `gates` verde; `PROGRESS.md` e memd no marco.
6. Todo `await` novo que cruza I/O ganha teste de crash (matar e reabrir).

Cada PR é independente; a ordem abaixo é por dependência técnica, não por

### Aceite do M4

- Matriz de durabilidade por tipo de efeito (tool nativa, MCP, code mode,
  subagente) com teste de crash em cada janela.
- `--mode rpc` com schema versionado e teste de reconexão.
- Nenhuma frente do M4 regride os gates do M2 (rodar o game day ao final).

## Decisões abertas

1. `--fork`: `at` explícito (`--fork <id> --at <entry>`) ou sempre a última
   entrada? Copiar ou não intenções pendentes?
2. `--name`: apelido no arquivo de sessão ou apenas açúcar para `--session`?
3. `--mode json`: compatibilidade byte a byte com o `pi` ou schema próprio
   versionado? (recomendo próprio, documentado)
4. Instruções: hierarquia até a raiz ou só cwd + pais até o repositório? Limite.
5. Compactação: política default do pacote ou ajustada por modelo (pequenos)?
6. MCP/code mode: quais servidores/scripts entram no v1 e como configurar.
7. Skills/templates: formato do Pi ou formato próprio compatível?

## Orçamento e parada

- Batch 0 + M2: 10 PRs; M4: 7 PRs. Cada PR com spec, teste, gates e auditoria.
- Regra de parada: terminar o PR corrente (gates + auditoria + merge) antes do
  próximo. O que não começar fica neste plano, não em branch aberta.
- Se um item do M4 exigir mudança de protocolo do pacote, parar e registrar no
  `PROGRESS.md` antes de continuar.
